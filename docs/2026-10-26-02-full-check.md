# 2026-10-26-02-full-check.md

Full check of Diffinery 0.1.0 against GitHub with **identical twin repos**: `github.com/joeblew999/diffinery-bench` and `diffinery.ubuntusoftware.net/gedw99/diffinery-bench`. The twin was made with Diffinery's GitHub importer and is kept identical with `mise run twin:sync` (GitHub wins). Supersedes the API and `gh` parts of [2026-10-26-01-first-comparison.md](2026-10-26-01-first-comparison.md), which compared against a different repo.

## 1. Importer

Imported in **about 20 s**: 3 branches, issue #2 and pull requests #1 and #3 **with their original numbers**, and 10 labels. Actions variables were skipped (they need a GitHub admin token). `main` matched commit for commit (`84f34cb`).

Problem: the imported merged PR #3 lists **0 commits and 0 changed files** on Diffinery (`/pulls/3/commits`, `/pulls/3/files`); GitHub lists 2 commits and 6 files.

| Job | GitHub | Diffinery |

A tie on a public repo (both 4 vCPU). Run-to-run variation is larger than the difference: Diffinery's Rust build took 46 s in the first comparison and 33 s here. A verdict needs several runs per side, and a private repo (where GitHub's standard runner is 2 vCPU).

## 3. API comparison (`mise run apidiff`, 28 REST endpoints)

**Matches GitHub:** pull requests (list, detail, reviews), issues over REST (list, detail, comments), commit status, branches list, file contents, README, labels, releases, tags.

**Incompatible:**

1. **GraphQL leaves out issues.** `repository { issues {…} pullRequests {…} }` returns only `pullRequests`, with no error.
2. **GraphQL issue creation is broken.** `createIssue` fails: `Variable "$input" expected value of type "CreateIssueInput!" which cannot be used as an input type`.
3. **Numeric IDs are strings** for workflow runs (`id`, `workflow_id`), jobs (`id`, `run_id`), workflows (`id`), check suites and apps.
4. **Thinner objects:** workflow runs lack `repository`, `head_repository`, `head_commit` and full `pull_requests[]`; jobs lack `created_at` and `labels`; workflows lack `node_id`, `url`, `html_url` and dates; check runs' `pull_requests[]` are thin; commits are not linked to accounts (`author.login`, `committer.login` missing); `/user` lacks `created_at` and `updated_at`.
5. **Relative refs in compare:** `/compare/main~1...main` returns 404 (the same compare with SHAs works).
6. **Imported PR has no commits or files** (see section 1).

Minor and harmless: `/actions/runs/{id}/logs` returns 200 (GitHub redirects with 302); `/contents/` with a trailing slash returns 200 (GitHub returns 400).

## 4. `gh` 2.89 against the twin (`mise run ghcheck:diffinery`)

"ok" means the command succeeded **and** its output showed the expected item.

| Works | Broken (repeatable) |

| `pr list`, `pr view`, `pr view --json`, `pr diff` | `issue create` (finding 2), `issue comment`, `issue close` |
| `label list`, `label create`, `label delete` | `workflow list`, `workflow run` (finding 3) |
| `release list` | `run list`, `run view` (finding 3) |
| `gh api` (REST) | |

`pr checks 3` is not comparable: imports don't bring CI history, so the twin's PR #3 has no checks. Single "Bad Gateway" failures (seen once on `pr list` and once on `release list`) were network blips in the Claude sandbox and passed on rerun.

The GitHub side of the `gh` check (`mise run ghcheck:github`) has to run from a normal `gh` login, such as a Mac: Claude cloud sessions block GitHub's GraphQL API, which most `gh` commands use.

## 5. Notes from setting this up

- Diffinery's CLI device sign-in pre-selects **write** even when the CLI asks for admin, so a person has to choose admin themselves. That's deliberate (`preselectedScope` in `web/cli-login.tsx`).
- The automatic mirror (Diffinery's GitHub Action) needs a `DIFFINERY_TOKEN` secret on GitHub, which a Claude session can't set. `mise run twin:sync` does the same job on demand.
