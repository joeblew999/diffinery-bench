# 2026-10-26-03-twin-ci.md

The twins test themselves. The same `check` workflow (`.github/workflows/check.yml`) ran on GitHub Actions and on Diffinery's CI, on the same commit. Each installed mise with `jdx/mise-action@v5`, ran `mise run check:self` against its own platform with its own job token, and uploaded its results. `mise run twin:collect` downloaded both and produced the comparison below.

## What this run adds

- **The kit itself is validated.** On GitHub, every `gh` check passes against GitHub (15 of 15), so a failure on Diffinery is Diffinery's, not the check's.
- **New: GraphQL ignores CI job tokens on Diffinery.** Inside Diffinery's CI, with the job token, every GraphQL-based `gh` command fails with `Could not resolve to a Repository with the name 'gedw99/diffinery-bench'`, even `repo view` and `pr list`, which work with a personal token. REST calls with the same token succeed. So any CI script on Diffinery that uses `gh` breaks.
- **Confirmed again:** numeric IDs as strings (`gh run list`, `gh run view`, `gh workflow list`), and the API differences from [2026-10-26-02-full-check.md](2026-10-26-02-full-check.md).
- **Works the same on both:** `actions/checkout`, `jdx/mise-action`, `actions/upload-artifact`, mise tasks, REST reads with the job token.
